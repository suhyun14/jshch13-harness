# 하네스 키트

작업을 일관된 절차로 진행하고, 결정과 검증 결과를 기록하기 위한 작업 하네스입니다.
요구사항 정리부터 계획, 구현, 검토, 인수인계까지 단계별 규칙과 문서 양식을 제공합니다.

## 구성
| 파일 | 용도 |
|---|---|
| `AGENTS.md` | Codex 작업 규칙과 단계별 진행 기준 |
| `templates/AGREEMENT.md` | 문제 정의, 성공 기준, 작업 범위와 제약을 기록하는 양식 |
| `templates/DECISIONS.md` | 주요 설계 선택과 이유를 기록하는 양식 |
| `templates/VERIFICATION.md` | 검증 결과와 알려진 약점을 정리하는 양식 |
| `templates/HANDOFF.md` | 현재 단계, 할 일, 실행 방법을 기록하는 양식 |
| `templates/STUDY_GUIDE.md` | 최종 코드의 흐름과 핵심 결정을 복습하고 설명하는 양식 |
| `prompts/PROMPTS.md` | 단계별 요청문과 인터뷰 질문 예시 |
| `commands/WSL_CODEX_CLI.md` | WSL과 Codex CLI 자주 쓰는 명령 모음 |
| `scripts/init.sh` | 규칙과 문서 양식을 과제 폴더에 복사하고 첫 커밋을 만드는 스크립트 |

## 시험 당일 사용법
먼저 과제 폴더(작업 공간)로 이동한 뒤, 그 위치에서 키트를 내려받고 초기화합니다. 아래 예시는 clone 후 생성되는 폴더 이름을 저장소 이름인 `jshch13-harness`로 통일합니다.
```bash
git clone https://github.com/suhyun14/jshch13-harness.git
bash jshch13-harness/scripts/init.sh .
codex
```
- `git clone`은 현재 폴더 아래에 `jshch13-harness`를 만듭니다.
- 초기화 명령은 그 폴더 안의 스크립트를 실행해 현재 과제 폴더에 `AGENTS.md`와 `docs/` 양식을 적용합니다. 기존 파일은 덮어쓰지 않으며, `docs/STUDY_GUIDE.md`도 생성합니다.
- `codex`는 과제 폴더에서 실행합니다. 필요하면 시작 후 `/model`에서 사용할 모델을 선택하세요.

단계별 요청문은 `jshch13-harness/prompts/PROMPTS.md`에서 확인하고 **[시작]**부터 진행 상황에 맞게 사용합니다.
WSL과 Codex CLI에서 자주 쓰는 명령은 `commands/WSL_CODEX_CLI.md`에 정리했습니다.
