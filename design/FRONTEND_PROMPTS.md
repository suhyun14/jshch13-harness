# 프론트엔드 디자인 단계별 프롬프트

> 그대로 복사해서 입력창에 붙여 쓴다. `< >` 부분만 바꾼다.
> 서비스 내용(대상, 핵심 가치, 기능, 제약)은 프롬프트에 직접 쓰지 않고 서비스 md 파일에서 읽게 한다.
> 한 단계씩 보내고, 결과를 확인한 뒤 다음 단계로 넘어간다.

---

## 어떤 정보를 어느 파일에서 읽는지
> 하네스 구성표(templates/ 양식의 용도)를 기준으로 정리했다. 과제 폴더에서는 init.sh가 docs/ 아래로 복사한 파일을 읽는다.

| 필요한 정보 | 읽을 파일 |
|---|---|
| 대상 (누가, 어떤 상황에서 쓰는지) | docs/AGREEMENT.md 1번 |
| 핵심 가치, 만들 기능 | docs/AGREEMENT.md 4번 (만들 것) |
| 성공 기준 | docs/AGREEMENT.md 3번 |
| 시간·기술·기타 제약 | docs/AGREEMENT.md 5번 |
| 확인 안 된 가정 | docs/AGREEMENT.md 6번 |
| 현재 단계, 할 일, 실행 방법, 주요 파일 | docs/HANDOFF.md |
| 이미 내린 설계 선택과 이유 | docs/DECISIONS.md |
| 검증 결과, 알려진 약점 | docs/VERIFICATION.md |

## [1단계] 서비스 파악 + 첫 화면 (네비 + 히어로)
```
AGENTS.md 규칙을 읽고 따라줘.
docs/AGREEMENT.md와 docs/HANDOFF.md를 읽고, 서비스의 대상·핵심 가치·만들 기능·제약을 먼저 세 줄 이내로 정리해줘.
정리한 내용만 근거로 랜딩 페이지 상단을 만들어줘. 네비게이션 + 히어로(제목, 설명, 버튼 2개, 오른쪽에 샘플 대시보드 패널)까지만.
문서에 없는 내용은 지어내지 말고 [확인 필요] 자리표시자로 두고, 수치는 [수치 입력]으로 둬.

[디자인 규칙]
- 컬러: Red #EA002C(버튼·경고, 흰 글자와 함께), Orange #F47725(아이콘·막대·표시점 같은 면에만),
  Ink #16120F(본문), White #FFFFFF(모든 배경), Stone #E8E1DC(구분선)
- 글자 강조는 진한 톤(빨강 #C8001F, 주황 #A84300), 흰 바탕 위 주황 글자는 금지
- 배경 전부 흰색, 각진 모서리, 얇은 선으로 구분
- 패널 모서리에 빨강·주황 단색 블록 2개, 선 그래프는 빨강→주황 30도 그라데이션 한 줄 선
- 폰트: Noto Sans KR + Space Grotesk
- 금지: 그라데이션 배경, 이모지, 둥근 카드, 보라색, 실제 기업 로고·이름
- 좁은 화면에서도 줄바꿈되는 반응형, 버튼 44px 이상
```
**확인할 것:** 정리한 서비스 내용이 문서와 맞는지, 색 값과 흰 배경과 분위기가 맞는지. 여기서 톤이 정해지면 뒤 단계는 거의 자동으로 따라온다.

## [2단계] 본문 섹션
```
docs/AGREEMENT.md 4번(만들 것)을 다시 읽고, 같은 톤으로 아래에 이어서 추가해줘.
1) 기능 카드 3개: 4번의 핵심 기능 3가지 (아이콘 박스는 빨강/주황/검정 면)
2) 시작 방법 3단계: 01, 02, 03 큰 숫자, 카드 상단에 굵은 선(빨강/주황/검정)
각 항목은 제목 한 줄 + 설명 한두 문장. 문서에 없는 내용은 [확인 필요]로 두고, 다른 부분은 그대로 둬.
```

## [3단계] 컬러 설명과 마무리
```
이어서 아래를 추가해줘.
1) 컬러 토큰 섹션: Red, Orange, Ink, White, Stone 스와치와 HEX
2) "이렇게 쓰기 / 피하기" 예시 카드 2개
   (쓰기: 흰 글자+빨강 면, 흰 바탕+검정 글자 / 피하기: 흰 바탕+주황 글자, 빨강 위 주황 면)
3) 빨강 CTA 밴드(이메일 입력 + 버튼)와 푸터
다른 부분은 그대로 둬.
끝나면 docs/HANDOFF.md 작업 목록에 완료 표시를 하고, 중요한 설계 판단이 있었다면 docs/DECISIONS.md에 한 줄 추가해줘.
```

```

```
```
빨강/주황 설정값을 <새 값>으로 바꿔줘. 다른 건 그대로 둬.

docs/AGREEMENT.md 3번(성공 기준)과 지금 화면을 대조해서 못 맞춘 부분만 알려줘.
코드는 수정하지 말고, 결과는 docs/VERIFICATION.md 1번에 기록해줘. 확인 안 한 건 '미검증'으로 표시해줘.
```

## [부록] 한 번에 보내는 통합 프롬프트 (선택)
단계별로 나누지 않고 한 번에 요청할 때 쓴다. 틀어지면 위 단계별 방식으로 돌아간다.

```
AGENTS.md 규칙을 읽고 따라줘.
docs/AGREEMENT.md와 docs/HANDOFF.md를 읽고, 서비스의 대상·핵심 가치·만들 기능·제약을 먼저 세 줄 이내로 정리해줘.
그 내용만 근거로 랜딩 페이지를 디자인해줘. 문서에 없는 내용은 지어내지 말고 [확인 필요]로, 수치는 [수치 입력]으로 둬.

■ 컬러 (이 값만 사용)
- Red #EA002C: 버튼, 경고, 핵심 강조 (흰 글자와 함께)
- Orange #F47725: 아이콘, 막대, 표시점 같은 면 요소에만
- Ink #16120F: 본문 / White #FFFFFF: 모든 배경 / Stone #E8E1DC: 구분선
- 글자 강조가 필요하면 진한 톤 사용 (빨강 #C8001F, 주황 #A84300)
- 흰 바탕 위 주황 글자, 빨강 위 주황 면은 피할 것

■ 디자인 모티프
- 배경은 전부 흰색, 섹션은 얇은 선으로만 구분
- 히어로 패널 모서리에 빨강·주황 단색 사각 블록 2개를 겹쳐 포인트로
- 선 그래프는 한 줄 선에 빨강→주황 30도 그라데이션
- 각진 모서리(radius 0), 넉넉한 여백
- 그라데이션 배경, 이모지, 둥근 카드, 보라색 계열 금지

■ 타이포
- 한글 Noto Sans KR, 영문/숫자 Space Grotesk
- 제목은 900 굵기로 크게, 본문 15~18px에 줄간격 1.7

■ 구조
네비게이션 → 히어로(제목 + 버튼 2개 + 샘플 대시보드 패널) → 기능 카드 3개
→ 시작 방법 3단계(상단 굵은 선 색을 빨강/주황/검정으로) → 컬러 토큰과 "이렇게 쓰기/피하기" 예시
→ 빨강 CTA 밴드(이메일 입력 + 버튼) → 푸터

■ 품질 기준
- 좁은 화면에서도 줄바꿈되도록 반응형으로
- 버튼 높이 44px 이상, 글자 대비 4.5:1 이상
- 실제 기업의 로고, 이름, 문구는 쓰지 말고 가상의 서비스 이름 사용
- 색상은 설정값에서 바꿀 수 있게 빨강/주황 두 값만 노출
끝나면 docs/HANDOFF.md 작업 목록에 완료 표시를 해줘.
```

## 요령
- **한 단계마다 결과를 보고 넘어간다.** 틀어진 부분은 그 단계 안에서 고치는 비용이 가장 적다.
- **수정 요청에는 "다른 건 그대로"를 붙인다.**
- **브랜드 가이드 캡처는 1단계에 같이 첨부한다.** 이후 단계에서 색이 흔들리지 않는다.
- **서비스 내용을 바꾸고 싶으면 프롬프트가 아니라 docs/AGREEMENT.md를 고친다.** 프롬프트는 그대로 두고 문서만 바꾸면 결과가 따라온다.
- **오렌지 값:** 브랜드 가이드의 HEX(#F47725)와 RGB 표기(255, 122, 0)가 서로 다르다. 위 프롬프트는 HEX 기준이고, RGB 쪽을 원하면 #FF7A00으로 바꾼다.
- **이름과 로고는 직접 교체한다.** 가상 서비스 이름을 유지하는 편이 안전하다.
